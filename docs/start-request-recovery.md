# 开始面试的请求回执与恢复

2026-11-03，增量迁移 `start-requests-v1`。不清理或重写已有面试记录。实际上线前仍须一致备份数据库和删除台账，并在离线副本验证迁移；本轮只迁移隔离测试数据库。

首页开始请求携带随机 `request_id`，浏览器按当前身份保存该标识与配置摘要。不会在该重试信息中存放背景、简历、回答或认证令牌。刷新后相同配置的未完成请求复用同一标识；账户切换/退出清理重试信息，浏览器标识24小时后在下次使用时替换。

服务端根据当前账户或有效游客凭据计算作用域，不接受客户端user_id。`start_requests` 以作用域与request_id为复合主键，保存参数摘要、处理状态与回执；账户记录受用户外键级联清理。正在处理的重复请求返回409，不再次派发AI；保存成功后，同一请求重试返回原场次，不再消耗AI额度。不同配置复用同一标识返回409。

面试主记录、首题、背景/配置快照与成功回执使用同一事务提交。服务重启后可读取成功回执；处理进程中断、没有可确认回执时标为结果未知，不自动再次付费调用。用户先从历史核对，确需重新开始时通过“我已核对历史，允许新建一场”建立新请求。服务明确返回失败时缓存失败结果，用户收到失败后下一次手动开始可建立新请求。

删除练习时，触发器清空回执中的问题/背景衍生内容，并保留不含正文的删除标记，旧请求不能复活已删除记录；迁移游客记录后原游客不能读取缓存首题，账户注销会清理关联回执。未关联记录的失败/未知/删除标记在7天后由后续启动请求清理；成功回执随对应记录保留。

兼容没有request_id的旧客户端，但旧客户端不具备此项重试保证。报告页重练入口随后在第08点接入同一回执与故障恢复机制，见[逐点记录](stepwise-optimization.md)。不承诺第三方在网络中断前是否已处理请求，回执机制不能撤销第三方已发生的费用。

回滚代码时保留新增表和删除清理触发器，无需清库或删除新表；旧业务表与字段不变。若需还原备份，仍使用包含删除台账的既有离线恢复工具，不能通过覆盖生产数据库撤销代码更新。
