# 账户、资料与审计改进交付

核对日期：2026-11-02。沿用 Flask、Werkzeug、原生 JavaScript、SQLite 和单进程 Waitress；没有改换框架、数据库或引入外部队列。项目根目录及上级、项目子目录未发现 AGENTS.md。账户无需新运行时依赖。

## 已实现的行为

- `/account` 提供注册、用户名密码登录、退出、资料修改、修改密码、退出其他设备和注销。导航显示称呼，个人中心链接本人历史与报告。
- 用户名以字母开头、3–32位字母/数字/下划线，按不区分大小写的数据库 UNIQUE 约束判重。昵称1–40字、支持中文；密码10–128字符、服务端核对确认密码，Werkzeug scrypt 哈希，不保存明文。
- 复用44个专业，支持“其他”；本科1–5、硕士1–3、博士1–5、专科1–3、已毕业及其他学习阶段。资料只在服务端保存，重新登录和服务重启后读取同一资料。
- 不依赖邮件或短信。没有自助密码找回，也不能凭昵称、专业等公开信息重置密码。知道当前密码且能登录时可修改密码；部署方后续若增加人工恢复，须另行建立可靠的身份核验流程。
- 游客入口保留；登录不会静默合并。个人中心显示本浏览器可迁移数量，勾选确认后才能迁移。服务端只认当前签名游客凭据，客户端不能提交任意记录ID。
- 报告逐题任务提供可保存重答、原回答和历次重答。当前仅保存，不调用AI、不重新评分；记录原评分版本，旧报告标为 `legacy-unversioned`。

## 数据模型与无损迁移

启动时 `database.init_db()` 执行幂等迁移 `accounts-v1`，用 `BEGIN IMMEDIATE` 包裹增量DDL。旧的面试、消息、报告和归属表保留，不清库、不批量重写原正文或分数。

新增：`users`、`user_profiles`、`auth_sessions`、`auth_attempts`、`schema_migrations`、`interview_profile_snapshots`、`reanswers`；补齐游客归属表与索引。`interviews` 只增加可空的 `owner_user_id` 外键和索引。旧记录保持游客归属；没有可验证归属凭据的旧记录保留，但不会向任意新账户公开或允许认领。

用户资料、会话、绑定面试及其消息、报告、背景、选择、回答回执、音频指标、重答和后台任务都有相应外键级联清理。迁移只更新当前游客凭据的 NULL 所有权行，事务化、重复请求返回0，已绑定行不可再次迁移。注销不会把记录转回游客。

## 会话、安全与接口约定

- `iv_auth` 是随机会话凭据，仅存在 HttpOnly、Secure、SameSite=Lax Cookie；数据库只保存其摘要。登录轮换凭据，退出在数据库撤销。默认有效期7天；修改密码默认撤销其他设备，可取消此选项，当前会话总会轮换。
- 游客凭据与登录会话分开，保留既有签名 Cookie，登录轮换不会丢失可迁移归属。公网试用游客 Cookie 为14天；清 Cookie、换浏览器或换域名后没有自助恢复保证，游客并非永久可靠存储。
- `/api/account/session` 返回当前身份、目录及 CSRF 同步令牌；令牌只放页面内存。所有API写操作须同时通过 Origin 同源检查和 `X-CSRF-Token`。GET `/api/report/<id>` 会启动/恢复任务，因此也要求该令牌。令牌不是登录凭据，不代替 Cookie。
- 会话、历史、状态、回答、结束、背景、报告生成、语音建议、音频关联、PDF、重答和删除均根据服务器当前身份判断归属。客户端 `user_id` 不参与身份认定。
- 注册限制：每IP每15分钟5次；登录限制：每IP30次、每用户名10次；修改密码/注销另有再次认证限制。只保存加密摘要的计数键。试用版原有AI并发配置1000和已放宽的AI日额度保留，认证限制独立生效。
- 普通日志只记请求号、接口名、耗时、状态和错误类型；不记录 Cookie、令牌、密码、简历、回答正文或原始异常内容。反向代理新增无正文、无查询串的计时日志格式。
- 所有动态HTML/API（包括错误和PDF）为 `no-store`；只对公开静态CSS/JS等缓存。前端身份变化清除旧会话、配置和回答草稿；草稿按身份、面试和题目隔离。其他标签页发现切换立即隐藏并回首页，旧页面禁止再写回草稿；浏览器返回缓存页面会重新核对并刷新。

主要账户API：GET `/api/account/session`；POST `/api/account/register`、`/login`、`/logout`、`/password`、`/claim-guests`；GET/PATCH `/api/account/profile`；DELETE `/api/account`。资料字段白名单、长度、目录值、密码一致性、重复用户名及数据库并发冲突均在服务器校验。

## 资料同意与历史快照

长期资料与单场背景分开。开始前确认岗位、难度和专业方向；账户专业、学习阶段默认不发送给模型，需本场重新勾选同意，服务器才加入出题背景。昵称只用于显示，不自动加入模型请求。不填背景也能练习。

本场配置快照只记录必要的专业、学习阶段、同意状态和版本，不复制姓名；修改资料不重写历史报告。已同意的独立背景可在面试中清除；结束时清除，最长24小时，读取时及每5分钟后台巡检清理。`test_background.py` 覆盖过期、结束清理和拒绝未同意背景；账户测试检查模型请求未出现昵称、未同意时未出现学习阶段。

问题、回答和自愿提供的背景发送给DeepSeek用于出题和反馈；语音在当前服务转写。撤销只影响后续请求，不能撤回已经发送给第三方的数据。自行把姓名写入回答/简历时属于用户主动提交内容，本功能不承诺完全自动识别和剔除所有个人信息。

## 删除、台账与恢复边界

注销需当前密码及输入“注销账户”，删除用户、资料、全部登录会话及绑定练习的关联数据。单场删除也清理相关数据。在途AI/语音调用可能不能立即中断，最终写入不能重建已删外键记录；临时上传音频在处理结束/退出时清理。新上传录音位于当前数据库旁的 `.speech-temp` 专用目录，文件名只含面试ID摘要及随机标识；注销/单场删除尝试清理本场文件，启动时清理已知格式的进程遗留文件，不递归删除未知目录或文件。强制重启测试验证清理已知音频、保留未知文件。升级前系统临时目录中无法可靠关联归属的旧残留不能安全自动认领或批量删除，需由管理员结合停机及系统临时文件策略审查。普通日志无正文，但现有备份、第三方已接收数据和正在执行请求的短暂内存不承诺即时擦除。

`<数据库路径>.deletions.jsonl` 只追加记录/用户ID的摘要、种类和时间，不存正文、密码或昵称；先持久化并同步磁盘，再提交删除。启动恢复时重放，防止旧备份复活已删除记录。台账是额外的防恢复记录，需要受限权限、独立备份和保留策略；如果较新的台账同时丢失，不能保证追溯备份之后的删除。

## 环境变量与启动

运行依赖仍为 `deploy/requirements.txt`。至少配置 `DEEPSEEK_API_KEY`；`DEEPSEEK_MODEL` 保持现有选择。没有AI配置时，账户功能仍可用，AI面试会返回明确的服务不可用提示。

本地HTTP开发：

```powershell
$env:APP_INSECURE = "1"
.\.venv\Scripts\python.exe app.py
```

打开 `http://127.0.0.1:5001`。生产HTTPS禁止启用 `APP_INSECURE=1`。固定 `SECRET_KEY` 或妥善保留 `.secret_key`；公网试用入口继续使用原 `.public-test/cookie.key`，不可随更新重建。试用运行：

```powershell
.\.venv\Scripts\python.exe tools/run_public_test.py
```

此入口监听回环5010，要求外部HTTPS，并使用 `.public-test/trials.db`；正式 `python deploy/wsgi.py` 使用 `interviews.db`，需HTTPS反代，保持单进程。源代码中 `SECURITY_TEST_BYPASS` 仅供旧隔离测试，严禁在运行环境开启。新账户与正式入口安全测试不使用该跳过开关。

## 备份、迁移与回滚

先备份数据库、Cookie签名密钥和删除台账。不要用普通文件复制替代运行中数据库的一致备份：

```powershell
.\.venv\Scripts\python.exe tools/account_store.py backup --database .public-test/trials.db --target D:/Backups/trial-before-accounts.db
.\.venv\Scripts\python.exe tools/account_store.py migrate --database .public-test/trials.db
.\.venv\Scripts\python.exe tools/account_store.py verify --database .public-test/trials.db
```

备份工具用SQLite一致备份API，目标必须是新文件，同时复制删除台账。迁移也在启动时自动执行。正式站将数据库参数替换为 `interviews.db`。备份和密钥不可入Git。

恢复必须停止应用，保留当前最新删除台账和签名密钥，再执行：

```powershell
.\.venv\Scripts\python.exe tools/account_store.py restore --database .public-test/trials.db --source D:/Backups/trial-before-accounts.db --offline
```

恢复工具先额外保存当前数据库，再合并备份台账与当前较新台账、恢复数据库、执行迁移和删除重放，并检查完整性。异机恢复也要取得最新独立台账；仅旧数据库备份无法证明后续删除已执行。权限、备份加密、离机保存、保留周期和定期恢复演练由部署方落实，当前Windows测试不等于云主机已配置定时备份。

本次迁移为增量迁移，首选保留新表和外键，前向修复或回退到具备同等权限保护的账户版。**不能把账户数据库直接交给旧的、只认识游客的公开版本运行**，否则旧历史查询可能忽略账户所有权。若必须整版回到升级前：停止公网入口、另存当前账户版数据库/台账、恢复升级前代码和数据库，在离线环境验证，再决定是否开放；这会丢失备份之后的新业务数据，应优先采用前向修复。没有通过删表/清库实现“回退”。

## P1、P2审计修复与证据

1. 历史页原 `.history-empty {display:grid}` 与通用隐藏样式竞争；统一 `[hidden]`、`.is-hidden` 的最终隐藏优先级，并用单一状态函数互斥加载、失败、空和有记录。浏览器覆盖有数据/失败/删除最后一条/游客与登录身份。
2. 新增 `X-Request-ID`、`Server-Timing: app, db, ai` 和无正文结构化计时；后台任务返回/记录独立摘要关联号。应用计时包括处理耗时，数据库计时覆盖连接、执行、提交与关闭（不是完整数据库剖析），AI计时覆盖SDK调用。应用之前的Waitress排队、网络、TLS、隧道不在应用计时内。正式代理配置记录请求与上游响应耗时；必须在云端验证后才能作更细归因。
3. 手机收起上一题长点评为可展开摘要，最后题保留展开；把录音控制靠近文字区，减少装饰占用。390px及缩小视口验证无横向溢出、提交按钮可到达；真实手机软键盘、微信内置浏览器仍需目标设备验收。
4. 用户文案去除实现/迭代用语，改为练习反馈。仅跳过的面试不调用评分模型，网页、历史、PDF显示未评分/未评估。数据库兼容旧非空数值列，以 `unassessed` 标记为准，API不把存储占位值当真实0分。新评分缺少合法数值时返回可重试失败，不凑零分。薄弱点需关联实际回答证据，去掉无依据精确掌握度；旧报告原数值保留并明确旧版本。
5. 重答保存走服务端权限、事务与唯一请求标识；响应丢失后同标识同内容重复提交不重复生成，不覆盖原回答和原报告。

## 测试与仍需生产验收

详见 `account-verification.md`。测试均使用虚构资料和独立临时数据库。外部DeepSeek调用以契约测试替身代替；不把替身结果当真实模型质量或服务可用性验证。Whisper/VAD相关旧测试按各脚本标明真实算法或替身。

以下必须在目标部署环境完成，当前不能声称已通过：

- `nginx -t`，核对代理只转发可信请求头、5010只监听回环、全站HTTPS，返回Cookie含Secure/HttpOnly/SameSite，所有动态响应no-store；私有内容不得被CDN共享缓存。当前机器没有Nginx，配置语法未在此执行。
- 两账户/一游客真实设备复测，跨站请求返回403、替换记录ID返回404，注销后旧会话失效；真实手机键盘不能遮挡可滚动到达的提交/录音操作。
- 指定预期并发与响应目标，用隔离数据逐步施压，检查TTFB分布、CPU/RAM、SQLite锁等待、任务积压、外部AI配额。1000只是现有配置上限，不等于经过1000人真实并发验证；现有内存锁仍要求单进程。
- 当前 `trycloudflare.com` 为临时试用隧道，网址和可靠性无长期保证。正式域名、固定隧道或目标云主机尚需单独落实，不应迁移数据库或拆服务来代替网络测量。
- 配置受限文件权限、日志轮换、备份保留/加密/离机存储，完成“备份 → 写入 → 删除 → 恢复 → 删除不复活”的目标机器演练，并检查任务、临时音频目录与最新台账。
- 真实DeepSeek质量与外部故障恢复、隧道断线及真实用户长期弱网仍需持续观察。当前覆盖的是浏览器断网和“服务端成功但响应丢失”的可复现测试。


生产验收建议记录固定版本、并发数和持续时间：先在隔离数据上跑10、25、50并发，每档至少10分钟，再逐步到双方确认的目标；建议以零越权、零丢失/重复业务写入、无数据库锁错误作为硬条件，错误率低于1%、主页应用P95低于200ms作为初始观察目标（待部署方确认，不代表本轮已达到）。报告进程中断后，重新访问应在运行默认90秒租约到期并完成一次外部调用后恢复；删除后恢复旧备份仍不得复活数据。达到CPU/RAM或外部配额瓶颈时应先停止继续加压并记录计时证据，不能用1000配置值代替容量结论。
