# 继续面试、手机导航和后台报告

## 使用方式

- 首页显示一场最近未完成面试；历史列表的进行中记录提供“继续面试”。读取本人当前题目与进度后再进入作答页，现有按题草稿保持独立，恢复计时和背景使用状态。
- 手机及平板顶栏提供“菜单”，可访问首页和历史等入口；支持键盘操作、Escape关闭和焦点提示。电脑保留原导航。
- 手动查看报告后，首次请求建立后台任务，立即返回排队或生成状态。页面每2秒读取结果，离开或刷新不会新建同一任务。最后一题仍停留在点评页面，由用户手动进入报告。
- 失败状态持久保存，普通刷新不自动重复调用AI；点击“重试加载报告”才重新排队。已存报告立即复用。

## 实现与恢复边界

新增 `report_jobs` SQLite关联表，状态为pending/running/done/failed。一个后台工作线程顺序生成报告；任务通过事务领取，处理期间每10秒续租90秒租约。服务中断后，重新访问报告会启动工作线程，在旧租约过期后恢复遗留任务。无需引入额外队列服务。

后台调用沿用现有AI包装、输出限制和并发配置。任务只保存用于配额计算的浏览器/IP摘要，不保存浏览器凭证；服务端接口继续检查面试归属，包含新增的手动重试端点。删除面试会级联清理任务。

显示“等待分析”和“AI正在分析回答并整理报告”两种真实状态，不展示模型无法提供的逐题百分比。任务后台执行改善等待与可恢复性，不承诺缩短模型本身耗时。

进程在云端已完成、结果尚未入库时被终止，恢复任务可能再次调用模型。这是当前恢复边界，不承诺跨服务故障的严格一次调用。仍按当前单进程部署运行，不直接扩大为多进程服务。

本次没有改变宽松使用限制，没有修改旧面试分数。正式部署入口的数据隔离问题仍单独待处理。

## 验证

- 隔离数据库：立即返回后台状态、页面离开后完成、重复读取只调用一次、失败不自动重试、手动重试、租约恢复与互斥领取、越权阻止、进行中不生成报告、删除级联。
- 真实浏览器：375/390/412px菜单及无横向溢出，首页和历史恢复题目与已有草稿，后台生成期间离开并返回、刷新读取已存报告、电脑导航。
- 原草稿、面试流程、报告恢复、PDF、专业选择、背景与使用限制回归。

历史同步回归测试使用显式的测试配置 `REPORT_JOBS_INLINE`，保持对原评分、缓存与导出行为的覆盖；新增任务及浏览器检查走默认后台流程。

公网实测通过：手机菜单、首页与历史继续面试保留草稿；真实AI报告首次请求约0.8秒返回202，后台完成后可离开、返回和刷新查看；其他浏览器无法重试此报告。临时记录已删除，原有57场面试、392条对话、14份报告内容均未改动。此耗时为本次单点观测，不是延迟保证。
