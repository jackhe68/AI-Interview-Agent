# AI Interview Agent 公网试用

当前网址：双击“启动公网试用.cmd”会自动打开浏览器；也可以打开同目录的“打开面试系统.url”，或查看“当前试用网址.txt”。这些文件会在启动时更新，不使用固定的旧网址。

这个 HTTPS 地址已经可以发给测试者。测试者直接在浏览器打开，允许麦克风，即可开始面试，无需安装项目。

## 使用时保持什么

- 你的电脑保持开机、联网，不进入休眠。
- 后台试用服务和访问隧道保持运行；不需要一直开着编辑器或聊天窗口。
- 一次识别一段录音；同时有人识别时，其他人会收到稍后重试提示，录音和草稿保留。
- 为小组测试设置了每天最多 30 次“开始面试”请求额度，失败尝试也计入；按日本时间每日重置，已有面试仍可继续。

## 启动、关闭与网址变化

附带“启动公网试用.cmd”和“关闭公网试用.cmd”，双击运行即可。它们使用 `D:\AI_Interview_Agent` 中的启动脚本。

启动脚本会显示中文进度；服务已经运行时，从隧道日志恢复实际网址，不重复启动，并自动打开浏览器。重新建立隧道后，临时网址可能变化，请以启动窗口显示的地址为准。当前地址也写入 `D:\AI_Interview_Agent\.public-test\public-url.txt`。

关闭操作只停止公网试用进程，不删除任何面试数据，不影响原本机 `http://127.0.0.1:5001` 入口。电脑重启后需要再次启动公网试用；没有修改开机启动项、路由器端口映射或电脑休眠设置。

## 记录如何保存

使用同一套 Flask、DeepSeek、faster-whisper 与音频分析代码，但试用记录单独保存在 `D:\AI_Interview_Agent\.public-test\trials.db`。

- 原 `interviews.db` 没有被公开或重置。
- 测试者只能通过当前浏览器查看和操作自己的试用记录，不能读取、结束或删除其他人的面试。
- 使用签名的 HTTPS 专用浏览器身份，历史和报告不公开缓存。
- 原始录音处理后删除，保存文字、评分与计算出的音频指标。
- 不同浏览器、无痕窗口或清除 Cookie 会形成新的身份。临时网址更换后，旧网址的浏览器身份不会自动迁移；旧数据仍保存在试用库中。

这是小组试用入口，不是带注册登录和身份找回功能的正式生产部署。后续如需稳定网址、跨设备历史及长期服务，需要继续完善部署和账号机制。

## aiinterview.bot.cd 的当前状态

**尚未绑定，未修改 DNSHE 中的解析或域名委派设置。**

本次使用的是 Cloudflare Quick Tunnel 临时地址。该模式直接生成 `trycloudflare.com` 地址，适合试用，停止隧道后地址失效。[官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

另外，Cloudflare 的普通 Free/Pro 域名接入要求域名位于 Public Suffix List 认可后缀的下一层。本次查到 `bot.cd` 不在该列表中，因此 `aiinterview.bot.cd` 不能直接按普通独立域名做免费委派接入；更低层的独立子域名接入属于另一种设置。[Cloudflare 域名接入要求](https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/)

不能将“能够设置 NS 委派”理解为“该域名可以直接接入任意平台的免费方案”。也没有将当前临时地址随意写成 CNAME，因为那不会自动完成自定义域名路由与 HTTPS 证书绑定。

后续固定使用 `aiinterview.bot.cd` 时，需要选定明确支持该自定义域名的公网入口，并取得相应账号/配置能力，再按该服务提供的目标配置 DNS。当前的临时 HTTPS 地址可以先用于用户测试。

## 本轮实际验证

1. 独立试用入口返回健康状态，公网 HTTPS 请求成功，浏览器处于安全上下文并能调用麦克风接口。
2. 5 组试用保护测试通过：浏览器身份、历史隔离、跨用户读写拒绝、来源校验、启动额度、音频归属及重复结束保护。
3. 真实公网浏览器 E2E 通过：真实 DeepSeek 首题与回答 → MediaRecorder 录制合成中文测试音频 → 实际 WebM 上传 → faster-whisper 转写 → 音频指标 → 手动提交 → SQLite → 真实评分及语音建议 → 报告显示。
4. 第二个浏览器读取第一人的报告返回 404，历史列表为空。
5. 真实公网链路没有 JavaScript 页面错误；该次合成试用数据已通过其所属浏览器的删除接口清理。
6. 启动、关闭、重新启动已验证；重新启动后当前网址的健康请求返回 200，原本机 5001 服务仍正常。
7. 原 ASR 接口 5 组测试和原面试评分/历史回归通过。

本轮浏览器音频测试使用合成中文输入，未声称完成人体麦克风、移动设备和真人识别准确率验收。测试者仍需实际录音检查。

## 新增运行组件与文件

新增小型 Windows 服务组件 Waitress 3.0.2；下载 Cloudflared 2026.10.7 Windows amd64，并核对 GitHub 官方发布中的 SHA256。没有安装新的音频依赖。

- `public_test.py`：只在试用进程安装的浏览器归属、来源检查、历史过滤、每日额度和音频并发保护。
- `tools/run_public_test.py`：在导入应用前选择独立试用库，使用 Waitress 监听本机 5010。
- `tools/start_public_test.ps1`、`tools/stop_public_test.ps1`：隐藏后台运行、进程启动时间校验、子进程清理、启动与关闭。
- `tools/requirements-public-test.txt`：固定 Waitress 版本。
- `tests/test_public_test.py`、`tests/test_public_browser.py`：隔离接口测试与真实公网浏览器测试。
- `static/js/interview.js`：音频请求始终携带面试 ID，关闭可选指标时也能检查录音归属。
- `.gitignore`：排除 `.public-test/`，避免提交试用数据库、Cookie 签名密钥、日志及隧道程序。

Cookie 签名密钥保存在本机受忽略的运行目录，未打印或导出。DeepSeek API Key 和 `.env` 内容未打印，也未修改 `.env`。
