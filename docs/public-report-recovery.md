# 公网入口与报告恢复修复

日期：2026-11-01

## 已确认的问题

1. 原一键部署每次关闭面试服务和隧道，日志记录了多次随机网址更换，旧分享链接会失效。截图中的当前链接已经是现运行链接，因此不能仅凭这个缺陷解释所有连接重置；手机网络中的重置仍未在本机复现。
2. 报告评分后同步等待可选语音建议；最终答案请求还可能先等待最后一次点评，再等待评分和语音建议。报告 GET 失败时又隐藏重试一次，导致单个请求串联多个长云端请求。
3. 报告前端把连接失败、非 JSON 网关响应以及页面渲染异常都归类为“网络异常”；结束按钮忽略请求失败也跳转报告页。

## 修改

- `tools/redeploy_public_test.ps1`：默认保留经 PID/启动时间验证的原隧道，只有隧道已退出或显式 `-RebuildTunnel` 才重建。不因单次健康探测超时主动换网址。
- `tools/stop_public_test.ps1` 和 `tools/start_public_test.ps1`：增加内部 `-KeepTunnel` 支持，更新应用进程时保留隧道记录，并在发布前继续要求真实 HTTPS 检查。原关闭操作默认仍关闭两个进程。
- `app.py`：结束接口先落库完成状态并返回；报告页单独请求评分。评分持久化后立即返回，语音建议由独立请求生成。每场报告只允许一个生成请求，其他请求得到 202 待生成，保存后刷新直接读取。移除同一报告请求内部的隐藏重试，保留具体 AI 错误与状态码。评分权重、提示的评分依据、数据库结构、10000 Token 设置和 50 路 AI 上限均保留。
- `static/js/report.js` 与 `report.html`：显示报告加载状态；202 自动等待；失败可重试，明确说明无需重做面试。区分网关非 JSON、连接失败、等待超时、记录权限与显示错误。评分显示后才自动单独请求语音建议，语音建议失败不隐藏报告。重复点击不并发发起报告请求。
- `static/js/interview.js`：结束请求失败时保留草稿并允许重试，成功后才进入报告页。
- `tests/test_report_recovery.py`：新增 5 组后端与真实浏览器故障恢复验证；调整输出上限与公网浏览器测试以验证独立评分/语音请求。

## 已完成验证

- Python、JavaScript 与 Windows PowerShell 语法检查通过。
- 新增报告恢复 5 组测试通过：结束不等 AI、评分与语音分离且缓存、明确超时且不隐藏重试、同时读取只生成一次、真实 Edge 中 HTML 502→重试→202→评分恢复且语音建议失败不隐藏评分；另在同一浏览器验证结束请求失败保留草稿、再次结束可跳转。
- API 保护 11 组、输出上限 2 组、语音分析关联 7 组、公网身份隔离 5 组测试通过。
- 3 个主问题与 3 个追问的原面试回归通过，评分权重、持久化、历史和删除正常。
- 实际执行桌面部署所调用的同一个脚本：应用进程更新、隧道 PID/启动时间/URL 未变化，公网健康检查成功。
- 更新后真实公网 Edge 全流程通过：首页点击开始、真实 DeepSeek 问题和回答、合成麦克风录音、真实 WebM 识别及声学分析、评分先显示、独立语音建议保存成功；无页面 JavaScript 错误，测试记录由所属浏览器删除成功。合成音频不代表真人识别准确率验收。

## 限制

未取得失败用户手机端的网络请求记录，不能保证已消除原始 ERR_CONNECTION_RESET；当前修复针对已确认的部署换址和报告调用设计问题。进程更新仍有短暂访问中断；关机或隧道退出后临时地址无法保证保留。语音识别仍是单任务。页面的“导出报告（模拟）”仍未实现 PDF 导出，本轮修复的是报告读取和生成恢复。
