# 开始面试失联与重新部署失败修复

日期：2026-11-02（Asia/Tokyo）。

## 已确认的原因

processes.json中的在用地址为organisations-polymer-shot-quote.trycloudflare.com；共用tunnel.err.log却含另一轮amplifier-homepage-favourite-begun.trycloudflare.com地址。旧启动脚本总从共用日志取最后一个URL，导致保留原隧道时反复检查另一个已失效地址。现场本机health与在用公网health均200，共用日志地址连接失败。日志还有不同进程重用同一文件留下的空洞与旧连接信息。

用户最初点击后失联的瞬间无法从已被覆盖的旧服务日志确定全部原因；没有证据证明点击动作导致服务崩溃。本轮实际公网开始、回答和刷新已经通过，不能将这个结果扩展为网络永久稳定。

## 修改

- tools/start_public_test.ps1：优先取已跟踪进程的保存地址；新隧道使用独立日志；原网址连续3次健康检查失败时，保留就绪的应用，仅重建一次隧道；公网检查通过后才更新桌面与分享快捷方式。保存状态使用临时文件替换，避免读取半个JSON。
- tools/redeploy_public_test.ps1：把服务重载与连接恢复交由同一个启动流程完成，不再提前从外部停止服务后盲目保留无效入口。补齐当前模块语法检查。
- tools/stop_public_test.ps1：与启动共用互斥锁，避免启动、停止和重部署交错覆盖状态。未知进程占用5010时不终止该进程，并关闭本项目已跟踪的旧隧道，避免把未知服务暴露出去。
- 原服务日志在重新加载前复制保留，便于下次判断退出原因，不再每次覆盖掉唯一证据。
- static/js/main.js：首题等待最长90秒，失败恢复按钮，不自动重试；提示先从历史核对服务器已保存记录。浏览器存储失败时留在当前页，明确提示允许本站存储及从历史继续，避免没有会话信息仍跳转造成循环。

没有改动账户、密码、会话归属、数据库结构或AI使用额度。
