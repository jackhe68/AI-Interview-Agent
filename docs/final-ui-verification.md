## 1. 点评在原区域展开

原始数据是一段完整点评，旧界面另外从同一段文字截取摘要放在summary中，展开后又显示全文，因此重复。现在同一份原文只写入一个文本节点，以CSS两行省略控制收起状态；展开解除限制，收起重新限制，不猜测或裁剪摘要/详情的关系，不丢失正文。

保留原details卡片和原生键盘操作，按钮切换“展开详情/收起详情”。标题、按钮与正文分行排列，长文本在卡片内换行。后台报告轮询也不会把用户手动收起的点评重新展开。

独立提交 `ebdfa1b`，先完成本点检查后才实施问题二。相关4个脚本通过（新增展开检查、原练习价值、草稿恢复及账户浏览器流程），共16项单元用例及脚本断言。

## 2. 面试完成页面

状态接口仅增加只读展示信息，依据已存面试状态、实际题目和逐题回答计算，不依赖浏览器文字或缓存：

- 正常完成：状态为finished、3道主问题已出现、所有已提问题有回答且无跳过，才显示“本场面试已完成”“已完成全部作答”“全部问题已完成”。
- 含跳过：明确显示跳过数量，不宣称全部作答。
- 主动结束或记录覆盖不足：使用结束文案，不宣称完成全部问题，也不把提前结束的进度补到100%。
- 尚未结束：保留原文字与语音作答区域，包括刷新后继续作答；本机缓存误标finished也不能提前隐藏控件。

确认结束后隐藏语音、麦克风、输入、提交、跳过、朗读/等待区域及原结束按钮，收起桌面装饰列和无效空白。保留最后题目、已保存的最后一题回答、完整点评和进度；完成卡片提供报告入口。

| 报告实际状态 | 按钮与说明 |
| --- | --- |
| 尚未生成 | 生成并查看报告，由原报告页启动生成 |
| 排队/生成中 | 报告生成中，禁用；只读查询状态，完成后恢复按钮 |
| 已生成 | 查看面试报告 |
| 失败 | 查看报告并重试；说明回答与点评保留，进入报告页手动重试 |
| 进程中断/租约失效 | 保留进入报告页恢复的入口，不永久停在禁用状态 |

没有修改报告任务派发、评分、DeepSeek或PDF核心。已有后端保护经验证：完成后的新回答返回409，清空内存会话后仍返回409，消息数不增加。原有同一request_id的成功回执仍可安全重放，不是接受新的回答；该幂等契约保留。

专项测试发现通用控件刷新曾重新启用“报告生成中”按钮，已将报告状态纳入统一禁用条件并复测。重启模拟用例另隔离了后台线程抢占，避免依赖测试时序。
