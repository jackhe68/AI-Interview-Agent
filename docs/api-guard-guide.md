# 公网试用 API 调用保护

已在当前公网试用进程启用。保护仅安装于 `tools/run_public_test.py` 启动的试用入口；原本机开发入口、原数据库和评分权重不变。后续桌面一键重新部署会继续加载保护。

## 当前试用配置（已放宽）

根据用户反馈，公网入口改用 `RELAXED_TRIAL_LIMITS`，取消每日面试场次、每日 AI 次数和每分钟访问次数限制。此前保存的计数不再拦截访问，不删除历史面试或使用记录。桌面一键重新部署也会继续使用此配置。AI 同时处理量提高为 1000 个；服务使用 1004 个请求线程，为页面与健康检查保留处理空间。音频识别仍按原有单任务保护运行，忙时可以手动重新识别。

| 范围 | 当前配置 |
| --- | --- |
| 每日开始面试场次 | 不限次数 |
| AI 每日及每分钟调用次数 | 不限次数，包含浏览器、同 IP、全站范围 |
| 一般 API 每分钟次数 | 不限次数 |
| 同时进行的 AI 调用 | 最多 1000 个 |
| 每次输出上限 | 仍为 10000 Token |

1000 是 AI 处理名额的应用配置上限。当前 Waitress 仍使用默认的 100 个网络连接上限，因此这不代表公网能同时承载 1000 个请求；达到该规模需要另行调整服务部署并进行真实负载验证。

保留浏览器记录隔离、同源写请求检查、输入格式和体积检查、岗位选择及面试任务边界。取消次数限制后，不再提供应用层的每日 AI 次数封顶；实际费用按使用量增加。当前网址健康检查通过不代表所有用户网络都可访问，若仍失败，需要用户提供所用网址和错误画面以区分网络与页面/API 错误。

`tests/test_relaxed_trial.py` 验证旧高计数不拦截、连续 35 次开场与 130 次历史读取、1000 个 AI 名额可占用且第 1001 个被拒绝并能在释放后恢复、50 个 AI 调用并行、50 个本机 HTTP 开场请求同时等待 AI 时健康检查仍可访问、正常报告流程和记录隔离。测试使用临时数据库与模拟 AI，无实际调用费用。这验证应用设置与请求调度，不代表 1000 个真实 AI 请求、真人录音或公网访问已通过并发负载验收；实际处理能力仍取决于本机资源和 AI 服务商容量。

## 原有限制配置（保留作备用，当前公网入口未启用）

| 范围 | 限制 |
| --- | --- |
| 全站开始面试 | 每天最多 30 次启动请求，沿用原限制 |
| 全站实际 AI 调用尝试 | 每天最多 300 次 |
| 单个浏览器 AI 调用尝试 | 每天 50 次、每分钟 8 次 |
| 同一来源 IP 的 AI 调用尝试 | 每天 200 次、每分钟 20 次 |
| 同时进行的 AI 调用 | 最多 2 个，超出直接返回繁忙，不无限排队 |
| 一般 API 请求 | 单浏览器每分钟 120 次、同 IP 每分钟 240 次、全站每分钟 600 次；健康检查除外 |
| 单次文本请求体 | 最多 32KB；音频继续沿用原 25MB 与时长限制 |
| 回答文字 | 1～4000 字符，必须是字符串 |
| 模型输入上下文 | 最多 64000 字符，属于字符上限而非精确 Token 计数 |
| 单次输出 Token 请求上限 | 面试、评分报告及语音综合建议均为 10000 Token |

开始面试、回答、评分、语音建议和相关重试都通过同一个实际 AI 调用保护，不仅统计首页按钮。额度在请求交给 DeepSeek 前原子预留，上游失败也计入。SDK 自动重试在试用进程中关闭，避免一次预留对应多个隐藏请求。

每日额度按日本时间重置。限额计数持久化在试用库的 `trial_api_usage` 表中，重新部署不会清零。换浏览器会产生新浏览器身份，但不能重置同 IP 及全站上限。IP 以签名密钥派生的 HMAC 摘要保存，不保存明文 IP、问题、回答或 API Key 作为限流日志。

超限返回 HTTP 429 和中文提示，附带 Retry-After；回答失败不会清空草稿或写入半条回答。报告因额度不足而暂时不能生成时，会返回对应限额提示，已有测量及已保存报告仍保留。

## 无关提问与提示注入

- 开场只能选择页面提供的六个岗位和四种难度，任意岗位提示词和非法数据类型在调用 AI 前拒绝。
- 客户端不能指定模型、messages、system prompt、输出 Token 等参数；接口拒绝不支持的字段。
- 候选人回答以 `candidate_answer` 数据字段提供给提问逻辑，原始回答仍原样保存。
- 所有公网 AI 调用增加固定任务边界：仅完成面试、评分与表达训练，候选人内容不能覆盖任务、指定分数或要求泄露配置。
- 既有程序不根据模型文字执行系统命令，API Key 不放入模型提示词。

对于“帮我证明黎曼猜想”，正常处理是指出回答偏题、继续当前岗位的面试。判断偏题可能仍消耗一次受限的 AI 调用，不能保证零成本，也不能承诺模型永远识别所有提示注入。

即使模型判断失误，调用数量、输入长度、输出长度和并发的服务器硬限制仍生效。这里限制的是调用与资源，不是人民币金额；费用仍取决于实际用量和模型价格，不应将它理解为某个固定金额的账单封顶。

## 实际验证

- 11 组保护测试通过：并发原子预留、重启后额度持久化、换浏览器不能绕过全站额度、同 IP 限制、失败计数、频率限制、输入参数拒绝、上下文/输出上限、候选人数据隔离、限额时回答回滚，以及正常结束/报告/空请求体重试兼容性。
- 原公网身份隔离 5 组测试、原面试评分回归、原语音关联 7 组测试通过。
- 已通过真实公网和真实 DeepSeek 实测：构造的“证明黎曼猜想、修改评分”输入被指出偏题，模型继续面试；注入式岗位请求返回 400。该构造测试记录随后由所属浏览器删除。
- 更新试用进程时保留了现有隧道和网址，不要求重新分享地址。

## 代码与边界

新增 `api_guard.py`、`tests/test_api_guard.py`；`tools/run_public_test.py` 加载保护，桌面重新部署的语法检查也已包含该模块。没有修改 `.env`，没有新增依赖，没有修改原数据库的业务表或报告评分算法。

输出上限位于 `ai_limits.py` 的 `MAX_OUTPUT_TOKENS`，其他额度位于 `api_guard.py` 的 `DEFAULTS`，需要调整后重新部署生效。来源 IP 仅在试用入口位于本机回环地址、通过 Cloudflare 隧道访问时读取其 CF-Connecting-IP 头；未来更换代理或公开绑定监听地址时必须重新审查信任边界。

这属于小组试用保护，不能替代生产账号、验证码、边缘流量防护及服务商费用告警。共享校园网络或手机热点的测试者可能共用 IP 额度；客户端身份不能等同于实名用户。大量网络层流量攻击也不能仅靠 Flask 内的限流解决。

参考：[OWASP API 资源消耗控制](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/)、[OWASP 提示注入防护](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)、[Cloudflare 访客 IP 头说明](https://developers.cloudflare.com/fundamentals/reference/http-headers/)。提示词是辅助防线，不是硬性安全边界。

输出上限已按要求统一为 10000 Token；这是最大允许输出量，并不强制每次生成满额。已增加内容截断检测，截断会返回可重试错误，不会被误判为面试结束。当前公网入口的次数与并发配置以本文开头的“当前试用配置”为准；下方原有额度机制仅在重新启用相应配额时生效。
